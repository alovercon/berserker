# berserker 用户手册

> berserker v0.2.0 — 开源 AI 编程助手，基于 LLM 提供代码生成、文件编辑、命令执行、多 Agent 编排等能力。

> **版本说明**：本文档内容已按 v0.2.0 当前代码核对更新（内置 Agent 名称、GUI 入口与行为、CLI 参数、工具参数、配置项等）。

## 1. 快速开始

### 1.1 最小配置

在项目根目录创建 `berserker.json`：

```json
{
  "providers": {
    "openai": {
      "type": "openai",
      "api_key": "{env:OPENAI_API_KEY}"
    }
  }
}
```

设置环境变量：

```bash
set OPENAI_API_KEY=sk-your-key-here
```

启动交互模式：

```bash
berserker.exe
```

### 1.2 指定项目目录

```bash
berserker.exe --project E:\0-works\coding\myproject
```

### 1.3 非交互模式（一次性问答）

```bash
berserker.exe run "解释一下这个项目的架构"
```

## 2. 启动方式

### 2.1 交互模式（默认）

直接运行，进入 REPL 对话循环：

```bash
berserker.exe
```

- 输入消息后按 Enter 发送
- 按 Ctrl+D 发送多行输入
- 按 Ctrl+C 中断（会询问是否退出）

### 2.2 指定项目目录

```bash
berserker.exe --project <目录路径>
```

`--project` 会将工作区设置为指定目录，所有文件操作限制在该目录内。

### 2.3 指定配置文件

```bash
berserker.exe --config /path/to/config.json
```

使用自定义配置文件，覆盖默认的配置文件搜索逻辑。

### 2.4 非交互模式（run 子命令）

```bash
berserker.exe run "你的消息内容"
```

- 消息也可以从 stdin 读取（管道输入）
- 支持 `--provider`、`--model`、`--session` 参数
- 响应输出到 stdout，适合脚本调用

### 2.5 GUI 模式

berserker 提供基于 wxPython 的图形界面，支持可视化对话、消息气泡、工作区切换、斜杠命令、Todo 展示、搜索消息等功能。

#### 安装 GUI 依赖

```bash
pip install wxPython
# 或使用可选依赖安装
pip install berserker[gui]
```

#### 启动 GUI

```bash
# 通过 Python 模块启动
python -m berserker.gui_entry
# 或指定项目目录
python -m berserker.gui_entry --project E:\0-works\coding\myproject

# 安装后也可使用 GUI 脚本
berserker-gui
```

> **注意**：**不存在 `berserker gui` 子命令**。直接运行 `berserker.exe`（无参数）启动的是 **CLI 交互模式**，不是 GUI。

#### 界面布局

GUI 界面采用**水平分栏**布局，从左到右分为侧栏和主内容区：

| 区域 | 说明 |
|------|------|
| **侧栏（250px 固定宽度）** | 工作空间名称、新建会话按钮、会话列表 |
| **工具栏** | 切换工作区（文件夹图标）、清除消息（删除图标） |
| **消息显示区** | 聊天消息的主要展示区域，支持垂直/水平滚动 |
| **搜索栏** | 按 Ctrl+K 打开，实时高亮匹配消息，Esc 关闭 |
| **动态组件区** | 自动显示 Todo 列表或选择交互组件（无内容时隐藏） |
| **输入区** | 多行文本输入框 + Send/Stop 按钮 + Agent/模型选择器 |
| **状态栏** | 四栏显示：运行状态指示器、状态文本、工作区路径、当前 Agent 名称 |
| **Agent 状态面板** | 右侧面板，实时显示所有运行中 Agent 的状态（Phase、Status、Task、Tokens），顶部有 Clear 按钮可清除所有条目 |

#### Agent/模型选择器

输入区底部提供 Agent 和模型选择器：

**Agent 选择器**：
- 下拉菜单显示所有可用 Agent（primary 和 subagent 类型）
- 选择后立即生效，后续消息使用新 Agent
- 状态栏实时显示当前 Agent 名称
- **Agent 运行时禁用**：Agent 执行过程中选择器被禁用，防止配置冲突
- 每个会话的 Agent 配置会持久化保存，切换会话后自动恢复

**模型选择器**：
- 下拉菜单显示当前 Provider 支持的所有模型
- 选择后立即生效，后续消息使用新模型
- **Agent 运行时禁用**：Agent 执行过程中选择器被禁用
- 模型切换不会影响 Agent 配置，仅改变使用的 LLM

**切换方式**：
- GUI：通过底部下拉菜单直接选择
- CLI：通过 `/agent <name>` 和 `/model <id>` 斜杠命令切换

#### 侧栏

侧栏位于界面左侧，固定宽度 250px，提供会话管理工作：

**工作空间标识**：
- 顶部显示当前工作空间名称（带蓝色圆点指示器）
- 点击工具栏文件夹图标切换工作空间后，侧栏自动更新

**新建会话**：
- 蓝色 "+ New Session" 按钮，点击创建新会话并立即切换

**会话列表**：
- 显示当前工作空间下的所有会话，格式为 `标题 (短ID)` 或 `(untitled) (短ID)`
- 点击会话项切换至对应会话，自动加载历史消息
- **右键点击**会话项弹出上下文菜单，可选择 "Delete Session" 删除会话
- 删除当前会话后，自动切换到其他会话或创建新会话

**会话切换行为**：
- Agent **运行时禁止切换会话**：切换按钮和会话列表点击会被禁用，防止状态冲突
- 切换会话时，前一个会话的 Agent 会被显式中止（abort）
- 切换后会加载目标会话的历史消息气泡
- 窗口标题实时更新为 `berserker <版本> — Session: <会话ID>`
- 每个会话的 Agent 配置（当前选择的 Agent）会持久化保存，切换后自动恢复

**会话恢复**：
- 启动 GUI 时，自动恢复该工作空间下最近一次使用的会话
- 仅当工作空间没有任何会话时，才会创建新会话

#### 消息气泡

消息以气泡形式展示，使用虚拟化列表（VListBox）渲染，支持海量历史消息无卡顿。

| 类型 | 颜色 | 对齐 | 头像 |
|------|------|------|------|
| 用户消息 | 浅绿 `#D1F4D1` | 右对齐，不超过 72% 宽度 | 👤 Twemoji 用户图标 |
| 助手消息 | 白色 `#FFFFFF` | 左对齐，不超过 72% 宽度 | 🤖 Twemoji 机器人图标 |
| 工具调用 | 浅灰 `#F0F0F0` | 左对齐，不超过 72% 宽度 | 🚧 Twemoji 图标 |

所有气泡使用 GraphicsContext 抗锯齿圆角（半径 14px），带细微边框。

**消息分组**：连续的同角色消息合并为一个视觉组，仅组的首条显示时间戳和头像，组内消息间距缩小。

**时间戳**：每组首条消息顶部显示发送时间（格式 `HH:MM:SS`），使用灰色小字体。

#### 右键菜单

在消息气泡上右键可弹出菜单：

- **复制**（Ctrl+C）：将当前消息全文复制到剪贴板
- **全选**（Ctrl+A）：将所有消息全文复制到剪贴板
- **删除**：从界面中移除该消息（仅 assistant/tool 消息，不影响数据库记录）

#### 双击查看详情

在消息气泡上**双击**可打开带可选择文本的对话框：

- 完整的消息原文，支持拖拽选中任意部分文字
- 可随意复制选中内容
- 对话框可调整大小

#### 搜索功能

- **打开**：Ctrl+K 或点击输入区快捷键提示
- **实时搜索**：输入关键词后即时高亮所有匹配消息（黄色背景 `#FFF3CD`）
- **结果提示**：通过 InfoBar 显示匹配数量（"Found 3 matches" / "No matches found"）
- **关闭**：Esc 键或点击搜索栏右侧 × 按钮，关闭后自动清除高亮

- **自动滚动**：加载完成后自动滚动到新加载消息的末尾

#### 斜杠命令

GUI 模式支持以下斜杠命令（在输入框中以 `/` 开头输入）：

| 命令 | 功能 |
|------|------|
| `/help` | 显示可用命令列表 |
| `/clear` | 清除消息并创建新会话 |
| `/agent <name>` | 切换 Agent（如 `/agent berserker`） |
| `/skills` | 列出已加载技能 |
| `/session <id>` | 切换到指定会话（仅支持切换，不支持 list/delete/compact） |
| `/start-work [name]` | 加载并执行工作计划（从 `.omo/plans/`） |
| `/compact` | 压缩当前会话上下文 |
| `/init` | 为当前工作区生成/改进 AGENTS.md |
| `/model <name>` | 切换模型 |
| `/exit` | 退出 GUI |

**`/agent` 命令详解**：

```
/agent              # 列出所有可用 Agent
/agent plan         # 切换到 plan Agent
/agent berserker       # 切换回主编程 Agent（berserker）
```

- 切换后立即生效，后续消息使用新 Agent
- 状态栏实时显示当前 Agent 名称
- **Agent 运行时不可切换**：Agent 执行过程中切换被禁止，防止配置冲突

**`/session` 命令详解**：

```
/session <id>       # 切换到指定会话（GUI 中仅支持此形式）
```

- Agent **运行时禁止切换会话**，需等待当前任务完成或手动停止后再切换
- 切换会话时，前一个会话的 Agent 会被显式中止
- 切换后自动加载目标会话的历史消息
- **不支持 `/session list`、`/session delete`、`/session compact`**；GUI 中删除会话请通过侧栏的右键菜单操作
- 每个会话的 Agent 配置会持久化保存，切换后自动恢复

#### 工作区管理

- **工具栏切换**：点击工具栏文件夹图标，弹出目录选择对话框
- **侧栏联动**：切换工作区后，侧栏自动刷新显示该工作区下的会话列表
- **状态栏显示**：当前工作区路径实时显示在状态栏中间
- **窗口标题**：切换工作区后标题变为 `berserker — <目录名>`
- **全局同步**：切换工作区后，所有工具自动使用新路径
- **会话隔离**：每个工作区的会话相互独立，切换工作区不会丢失其他工作区的会话

#### 动态组件

**Todo 列表**：
- 以可折叠面板（CollapsiblePane）形式展示
- 使用 CheckBoxList 显示待办事项
- 支持展开/折叠切换

**选择交互**：
- 当 Agent 需要用户选择时自动显示
- 使用 RadioBox 展示选项列表
- 支持自定义文本输入（allow_custom 模式）
- 选择后自动提交结果给 Agent

#### 处理状态指示

- **Activity Indicator**：Agent 运行时显示旋转加载动画
- **Send 按钮**：处理中时禁用（灰色），就绪时启用（蓝色）
- **Stop 按钮**：处理中时启用（红色），就绪时禁用（灰色）
- **状态栏**：处理中显示 "Processing..."，就绪显示 "Ready"
- **输入框**：Agent 运行时**完全禁用**（无法输入文本、无法使用 Enter/Up/Down 键）
- **新建会话按钮**：处理中时禁用，防止创建新会话
- **Agent/模型选择器**：处理中时禁用，防止切换配置

#### 停止执行（Abort）

点击 Stop 按钮可中断正在运行的 Agent 执行：

- **Abort 机制**：由于 `provider.chat()` 是阻塞式 HTTP 调用，无法真正中断网络请求。系统会在每次工具调用循环迭代前检查 abort 信号，若已设置则丢弃响应并退出
- **保留已执行的气泡**：Abort 后，本次执行过程中**已执行（executed）的工具调用气泡会被有意保留**，不会自动移除——因为 Agent 在每次工具调用后已把结果持久化到会话存储中，若移除气泡会导致界面历史与存储不一致
- **状态提示**：Abort 完成后状态栏显示 "Execution stopped"

#### 会话切换与 Agent 执行

- **Agent 运行时禁止切换会话**：切换按钮和会话列表点击被禁用，防止状态冲突
- **切换中止前一个 Agent**：切换会话时，前一个会话的 Agent 会被显式中止（通过 abort 事件）
- **Agent 配置持久化**：每个会话保存其当前选择的 Agent，切换后自动恢复
- **UI 状态管理**：Agent 完成后，无论当前处于哪个会话，UI 控件（输入框、按钮、选择器）都会自动恢复可用状态
- **新建会话限制**：Agent 运行时，"+ New Session" 按钮被禁用，防止创建新会话
- **删除当前会话**：若删除正在查看的会话，系统自动切换到其他可用会话或创建新会话

#### 桌面通知

任务完成或重要事件发生时，通过 `wx.adv.NotificationMessage` 弹出系统级桌面通知。

#### 欢迎信息

首次启动时自动显示欢迎消息，包含键盘快捷键提示和右键操作说明。

## 4. 斜杠命令

在交互模式中，以 `/` 开头的输入会被识别为命令：

| 命令 | 说明 | 示例 |
|------|------|------|
| `/help` | 显示帮助信息 | `/help` |
| `/exit` 或 `/quit` | 退出交互模式 | `/exit` |
| `/clear` | 清空对话历史（创建新会话） | `/clear` |
| `/model <id>` | 切换模型 | `/model openai/gpt-4o` |
| `/agent [name]` | 切换 Agent 或列出可用 Agent | `/agent plan` |
| `/skills` | 列出可用的 Skill | `/skills` |
| `/session <id>` | 切换到指定会话 | `/session ses_abc123` |
| `/compact` | 触发上下文压缩 | `/compact` |
| `/agents` | 显示实时 Agent 状态 | `/agents` |
| `/init [focus]` | 为当前工作区生成 AGENTS.md | `/init python backend` |
| `/start-work [name]` | 执行计划 via executor Agent | `/start-work agent-team-transform` |

**`/agent` 命令详细说明**：

```
/agent              # 列出所有可用 Agent 及其模式（primary/subagent/hidden）
/agent plan         # 切换到 plan Agent
/agent berserker       # 切换回主编程 Agent（berserker）
```

- 切换后立即生效，后续消息使用新 Agent
- 状态栏实时显示当前 Agent 名称
- **Agent 运行时不可切换**：Agent 执行过程中切换被禁止，防止配置冲突
- GUI 模式下，也可通过底部的 Agent 下拉菜单进行切换

**`/model` 命令详细说明**：

```
/model              # 列出当前 Provider 支持的所有模型
/model gpt-4o       # 切换到 gpt-4o 模型
/model claude-3.5-sonnet  # 切换到 Claude 模型
/model qwen-plus    # 切换到 Qwen 模型
```

- 切换后立即生效，后续消息使用新模型
- 模型切换不影响 Agent 配置，仅改变使用的 LLM
- **Agent 运行时不可切换**：Agent 执行过程中模型切换被禁止
- GUI 模式下，也可通过底部的模型下拉菜单进行切换

**CLI 与 GUI 切换对比**：

| 操作 | CLI 方式 | GUI 方式 |
|------|----------|----------|
| 切换 Agent | `/agent <name>` | 底部 Agent 下拉菜单 |
| 切换模型 | `/model <id>` | 底部模型下拉菜单 |
| 列出 Agent | `/agent` | 下拉菜单展开查看 |
| 列出模型 | `/model` | 下拉菜单展开查看 |
| 运行时切换 | 禁止 | 禁止（选择器被禁用） |

**`/session` 命令详细说明**：

```
/session              # 列出当前工作区下的所有会话
/session <id>       # 切换到指定会话
```

- Agent **运行时禁止切换会话**，需等待当前任务完成或手动停止后再切换
- 切换会话时，前一个会话的 Agent 会被显式中止
- 切换后自动加载目标会话的历史消息
- **不支持 `/session delete <id>`**：`delete` 会被当作会话 ID 处理（提示 "Session 'delete' not found"）。CLI 中删除会话请使用 `berserker session delete <id>` 子命令
- 每个会话的 Agent 配置会持久化保存，切换后自动恢复

### 4.1 `/init` 命令详解

`/init` 会扫描工作区中的关键配置文件（README、package.json、pyproject.toml、Makefile、CI 配置等），然后调用 LLM 生成一份 `AGENTS.md` 指令文件。

```
/init                    # 生成基础 AGENTS.md
/init python backend     # 指定关注点：Python 后端
/init focus on testing   # 指定关注点：测试相关
```

如果工作区已存在 `AGENTS.md`，会在现有内容基础上改进，而非完全重写。

### 4.3 `/agents` 命令详解

`/agents` 显示当前所有 Agent 的实时状态，包括名称、状态、当前任务和运行时长。

```
/agents
```

**输出示例**：
```
Agent Status:
Agent           Status       Task                           Duration  
----------------------------------------------------------------------
berserker-ses_abc  running      Executing 2 tool(s): read, grep  3.2s      
explore-ses_def completed    Completed (5 iterations, 12340 tok)  15.7s  
```

**状态说明**：
| 状态 | 说明 |
|---|---|
| `idle` | 空闲，未执行任务 |
| `running` | 正在执行 |
| `completed` | 执行完成 |
| `failed` | 执行失败 |

**GUI 模式**：
- 右侧面板实时显示所有 Agent 状态
- 5 列均分显示：Agent、Phase、Status、Task、Tokens（迭代次数和 token 数）
- 颜色编码：运行中（蓝色）、已完成（绿色）、失败（红色）
- 顶部 **Clear** 按钮可一键清除所有状态条目（包括卡在 running 的残留条目）
- 每秒自动刷新

**CLI 模式**：
- `/agents` 已在命令注册表（`berserker/command/builtin.py`）中注册，但当前交互式 CLI 尚未分发该命令（输入会提示 "Unknown command"）
- 状态栏底部显示当前 Agent 名称

### 4.4 `/start-work` 命令详解

`/start-work` 用于加载并执行已生成的工作计划。它会自动切换到 `executor` Agent，将计划内容注入上下文，然后开始执行。

```
/start-work                    # 列出可用计划
/start-work agent-team-transform # 执行指定计划
/start-work agent-team-transform.md  # 也可带 .md 扩展名
```

**执行流程**：
1. 在 `.omo/plans/` 目录中查找计划文件（支持精确匹配和部分匹配）
2. 验证 `executor` Agent 是否已配置
3. 如果当前 Agent 不是 `executor`，自动切换并打印提示
4. 读取计划内容，构建执行消息
5. 保存到会话历史，触发 executor 执行

**异常处理**：
| 场景 | 处理方式 |
|---|---|
| 计划文件不存在 | 报错，不切换 Agent |
| executor 未配置 | 报错，不切换 Agent |
| 读取计划失败 | 报错，不切换 Agent |
| 保存会话失败 | 报错，回滚 Agent 切换 |
| 执行中 Ctrl+C | 通过现有 abort 机制中断 |
| 工具执行失败 | executor 自行处理（重试/跳过/报告） |

**GUI 模式**：
- 执行 `/start-work` 后，Agent 下拉框自动切换到 `executor`
- 模型下拉框同步更新为 executor 配置的模型
- 状态栏实时显示当前 Agent 名称
- 执行完成后保持在 executor，用户可手动切换回去

**CLI 模式**：
- 执行 `/start-work` 后，打印 "→ Current agent is X, switching to executor"
- 执行完成后保持在 executor

## 6. 工作区管理

### 6.1 工作区设置

工作区通过 `--project` 参数设置：

```bash
berserker.exe --project E:\0-works\coding\myproject
```

- 相对路径会被转换为绝对路径
- 未指定时默认为 `os.getcwd()`（当前工作目录）
- 工作区在启动时设置一次，全局共享

### 6.2 工作区安全

所有文件工具都使用路径安全校验：

- 相对路径解析基于工作区根目录
- 防止路径穿越（`../` 无法逃逸工作区）
- 所有读写操作限制在工作区内

### 6.3 工作区启动流程

1. **CLI 解析**：`cli.py:main()` 解析 `--project`，转换为绝对路径
2. **设置工作区**：`conversation.py:start_conversation()` 调用 `set_workspace(workspace)`
3. **配置加载**：`load_config(cwd=get_workspace())` 在工作区中搜索项目配置
4. **Agent 初始化**：工作区注入到系统提示和 ToolContext
5. **工具使用**：所有工具通过 `ctx.extra["workspace"]` 读取工作区进行路径安全校验

## 8. 权限控制

### 8.1 默认权限

| 工具 | 默认权限 |
|------|----------|
| `read` | allow（允许） |
| `ls` | allow（允许） |
| `glob` | allow（允许） |
| `grep` | allow（允许） |
| `write` | ask（询问） |
| `edit` | ask（询问） |
| `multiedit` | ask（询问） |
| `apply_patch` | ask（询问） |
| `bash` | ask（询问） |
| `task` | ask（询问） |
| `mkdir` | ask（询问） |
| `rmdir` | ask（询问） |
| `mv` | ask（询问） |
| `cp` | ask（询问） |
| `rm` | ask（询问） |
| `touch` | ask（询问） |

> **注意**：未在默认权限列表中列出的工具（如动态注册的 skill 工具），默认行为为 `ask`（询问）。

### 8.2 权限规则

规则按顺序匹配，**第一条匹配的规则生效**：

```json
{
  "permissions": [
    { "tool": "read", "action": "allow" },
    { "tool": "write", "action": "allow", "path": "src/**/*.py" },
    { "tool": "write", "action": "deny", "path": "*.json" },
    { "tool": "bash", "action": "allow", "path": "scripts/*" }
  ]
}
```

- `tool`：工具名称
- `action`：`allow`（允许）、`deny`（拒绝）、`ask`（询问）
- `path`：可选，glob 模式的路径匹配

### 8.3 用户配置优先级

**用户在 `config.json` 中配置的权限规则优先于默认规则**。系统启动时会将用户规则插入到规则列表的开头，确保用户配置最先匹配。

例如，若你在 `config.json` 中配置：
```json
{
  "permissions": [
    { "tool": "mkdir", "action": "allow" }
  ]
}
```
则 `mkdir` 工具将自动允许，不再询问。

### 8.4 Skill 工具权限

Skill 系统会为每个发现的 skill 动态注册独立工具（如 `pdf`、`curl`、`acoreos3-project-builder`）。这些工具的权限控制方式与普通工具相同：

```json
{
  "permissions": [
    { "tool": "pdf", "action": "allow" },
    { "tool": "curl", "action": "allow" },
    { "tool": "acoreos3-project-builder", "action": "allow" }
  ]
}
```

> **注意**：`_ALL_TOOL_IDS` 中的 `"skill"` 指的是通用 skill 加载器（`skill` 工具），允许 agent 动态加载任意 skill 的指令。而每个独立 skill 工具（如 `pdf`）是单独注册和权限控制的。

## 11. Agent 配置

### 11.1 Agent 架构

berserker 使用基于类的 Agent 框架，取代了旧版 `AgentInfo` 数据结构。新架构提供：

- **`BaseAgent`**：抽象基类，定义 Agent 接口（`name`、`mode`、`execute()` 等）
- **`BuiltInAgent`**：内置 Agent 实现，封装 `berserker`（原 build）、`plan`、`executor`、`general`、`explore` 等
- **`CustomAgent`**：用户自定义 Agent，通过配置创建
- **`AgentRegistry`**：线程安全的 Agent 注册表，支持 CRUD 操作
- **`AgentSchema`**：基于 schema 的配置验证

> **注意**：旧版 `AgentInfo` 已被弃用，请使用新的 Agent 类体系。

### 11.2 内置 Agent

| Agent | 模式 | 说明 |
|-------|------|------|
| `berserker` | primary | 主编程 Agent（原 build），具备意图识别、代码评估、委托子 Agent 能力 |
| `plan` | primary | 规划 Agent，生成详细工作计划并保存到 `.omo/plans/` |
| `executor` | primary | 执行 Agent，读取计划、拆解任务、委托子 Agent 并行执行 |
| `consultant` | subagent | 咨询 Agent，预规划分析，识别隐藏意图和歧义 |
| `critic` | subagent | 审查 Agent，评估工作计划的清晰度、可验证性和完整性 |
| `general` | subagent | 通用子 Agent，具有完整工具访问权限 |
| `explore` | subagent | 探索 Agent，用于代码库探索和模式发现 |
| `compaction` | hidden | 上下文压缩 Agent |
| `title` | hidden | 会话标题 Agent |
| `summary` | hidden | 会话摘要 Agent |

### 11.2.1 Agent 团队架构

berserker v0.3.0 引入了多 Agent 协作架构：

**核心工作流**：
```
用户 → berserker（意图识别）→ plan（生成计划）→ executor（执行计划）
                                    ↓
                          consultant（预分析）→ critic（审查）
                                    ↓
                          general/explore（子任务执行）
```

> **工单处理团队（ticket-lead / ticket-fixer / ticket-qa）已移除**：该团队及其配置文件（`berserker/agent/configs/ticket-*.json`）已不再随发行版打包，`berserker/agent/configs/` 目录当前为空，对应的《工单处理团队使用指南》文档也已移除。启动器（`cli.py` / `gui/app.py`）仍保留了对 `agent/configs/ticket-*.json` 的扫描加载逻辑，因此如有需要，可自行放入这些配置文件重新启用（配合 `tea-gitea` skill 实现 Gitea 工单自动化），但不再提供内置配置。

### 11.3 Agent 模式

| 模式 | 说明 |
|------|------|
| `primary` | 主用户交互 Agent |
| `subagent` | 委托任务的子 Agent |
| `hidden` | 内部工具 Agent |

### 11.4 权限级别

| 级别 | 说明 |
|------|------|
| `full` | 允许所有工具 |
| `restricted` | 工具需通过权限检查 |

### 11.5 自定义 Agent

```json
{
  "agents": [
    {
      "name": "code-reviewer",
      "mode": "subagent",
      "model": "claude-3.5-sonnet",
      "prompt": "You are a senior code reviewer...",
      "tools": ["read", "grep", "glob", "ls"],
      "description": "代码审查专家 Agent",
      "permission": "restricted",
      "options": {
        "max_tool_iterations": 50,
        "max_tool_output_chars": 50000
      }
    }
  ]
}
```

### 11.5.1 提示词追加模式 (`prompt_append`)

默认情况下，配置 `prompt` 字段会**完全覆盖**内置 Agent 的系统提示词。如果只想在内置提示词基础上**追加**额外指令，可以使用 `prompt_append` 字段：

```json
{
  "agents": [
    {
      "name": "berserker",
      "prompt_append": "\n\n项目特定要求：\n- 优先使用 Python 3.10+ 特性\n- 所有函数必须包含类型注解\n- 禁止使用 eval/exec"
    }
  ]
}
```

> **注意**：覆盖内置 Agent（如 `berserker`）必须走**旧版配置路径**（`AgentManager.load_from_config`，即 CLI/GUI 启动时对 `config.json` 中 `agents` 段的处理），它会覆盖内置 Agent 的模型/提示词/工具配置。而基于 `AgentSchema` 的配置加载路径（`load_from_file` / `load_from_config_dict` / `discover_and_load`）会**跳过与内置 Agent 同名**的条目（内置优先），因此仅新增**全新命名的自定义 Agent** 时该路径才适用。

**行为规则**：
- 仅配置 `prompt_append`：追加到内置提示词末尾，保留 Agent 核心行为定义
- 同时配置 `prompt` + `prompt_append`：`prompt_append` 被忽略，以 `prompt` 为准（完全覆盖模式）
- 追加内容与原提示词之间自动插入两个换行符（`\n\n`）分隔

**使用场景**：为内置 Agent 添加项目规范、编码约束或特殊偏好，无需复制完整的内置提示词。

### 11.6 Agent Options 参数

Agent 的 `options` 字段支持以下可配置参数：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_tool_iterations` | int | 100000 | 工具调用循环最大迭代次数（防止无限循环） |
| `max_tool_output_chars` | int | 64000 | 单个工具输出的最大字符数（超出时自动截断） |
| `tools` | string[] | - | 允许的工具列表（仅 `permission: "restricted"` 时生效） |

**`max_tool_iterations` 说明**：
- 控制 Agent 在单次执行中最多能进行多少轮工具调用
- 默认值 100000 足够应对复杂任务
- 对于简单任务，可降低此值以节省资源

**`max_tool_output_chars` 说明**：
- 控制单个工具输出（如 bash 命令结果）的最大字符数
- 超出阈值时，输出会被截断并添加提示信息
- 默认值 64000 字符（约 16K tokens）
- 对于需要查看完整输出的场景，可增大此值

**配置示例**：

```json
{
  "agents": [
    {
      "name": "berserker",
      "mode": "primary",
      "model": "qwen-plus",
      "options": {
        "max_tool_iterations": 100000,
        "max_tool_output_chars": 64000
      }
    },
    {
      "name": "quick-helper",
      "mode": "subagent",
      "model": "gpt-4o-mini",
      "options": {
        "max_tool_iterations": 10,
        "max_tool_output_chars": 8000
      }
    }
  ]
}
```

### 11.7 切换 Agent

在交互模式中：

```
/agent              # 列出所有可用 Agent
/agent plan         # 切换到 plan Agent
/agent berserker       # 切换回主编程 Agent（berserker）
```

**GUI 模式下的 Agent 切换**：

- 通过底部 Agent 下拉菜单直接选择
- 通过 `/agent <name>` 斜杠命令切换
- 切换后状态栏实时显示当前 Agent 名称
- **Agent 运行时不可切换**：Agent 执行过程中，Agent 选择器被禁用，防止配置冲突
- 每个会话的 Agent 配置会持久化保存，切换会话后自动恢复

## 12. 内置工具

berserker 提供一组内置工具，供 Agent 在对话中调用以执行文件操作、代码搜索、Shell 命令、LSP 查询等任务。所有工具调用均受权限系统控制，且文件操作限制在工作区范围内。

### 12.1 文件工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `read` | 读取文件内容，支持指定行范围 | allow |
| `write` | 写入文件（覆盖或新建） | ask |
| `ls` | 列出目录内容 | allow |
| `glob` | 按 glob 模式搜索文件 | allow |
| `mkdir` | 创建目录（支持嵌套） | ask |
| `rmdir` | 删除目录 | ask |
| `mv` | 移动/重命名文件/目录 | ask |
| `cp` | 复制文件/目录 | ask |
| `rm` | 删除文件 | ask |
| `touch` | 创建空文件或更新时间戳 | ask |

> **提示**：对于文件/目录的创建、删除、移动、复制操作，**优先使用专用工具**而非 `bash` 命令。`bash` 仅应用于 git、包管理器、构建工具等复杂 shell 操作。

#### `read` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | 是 | 文件路径（相对或绝对） |
| `start_line` | integer | 否 | 起始行号（1-based，含端点） |
| `end_line` | integer | 否 | 结束行号（1-based，含端点） |

#### `write` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | 是 | 文件路径 |
| `content` | string | 是 | 要写入的内容 |

#### `ls` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 目录路径 |

#### `glob` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pattern` | string | 是 | glob 模式（如 `**/*.py`） |
| `root` | string | 否 | 搜索根目录（默认工作区） |

#### `mkdir` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 要创建的目录路径（自动创建父目录） |

#### `rmdir` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 要删除的目录路径 |
| `recursive` | boolean | 否 | 是否递归删除内容（默认 false，仅允许空目录） |

> **注意**：`recursive=false` 时，若目录非空会报错。需使用 `recursive=true` 才能删除含内容的目录（等同于 `rm -rf`）。

#### `mv` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source` | string | 是 | 源文件/目录路径 |
| `destination` | string | 是 | 目标路径（若为已有目录，则移入该目录） |

#### `cp` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source` | string | 是 | 源文件/目录路径 |
| `destination` | string | 是 | 目标路径 |
| `recursive` | boolean | 否 | 是否递归复制目录（默认 false） |

#### `rm` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 要删除的文件路径（不支持目录，删除目录请用 `rmdir`） |

#### `touch` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 要创建/更新的文件路径（自动创建父目录） |

### 12.2 编辑工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `edit` | 精确字符串替换（替换全部匹配项） | ask |
| `multiedit` | 同一文件内多处替换 | ask |
| `apply_patch` | 应用 unified diff 补丁 | ask |

#### `edit` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | 是 | 目标文件路径 |
| `old_text` | string | 是 | 要替换的原文 |
| `new_text` | string | 是 | 替换后的新内容 |

> **注意**：`edit` 会替换文件中**所有**匹配 `old_text` 的片段（`content.replace(old_text, new_text)`），并非"单处唯一替换"。若需在多个位置做不同的替换，请使用 `multiedit`。

#### `multiedit` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | 是 | 目标文件路径 |
| `edits` | array | 是 | 替换列表，每项含 `old_text` 和 `new_text`（按倒序应用） |

> **注意**：`multiedit` **没有** `replaceAll` 参数；每个编辑项与 `edit` 一样会替换该 `old_text` 的所有匹配。

#### `apply_patch` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | 是 | 目标文件路径 |
| `patch` | string | 是 | unified diff 格式补丁 |

> **注意**：`apply_patch` **没有** `strip` 参数。

### 12.3 搜索工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `grep` | 正则表达式内容搜索 | allow |
| `websearch` | 互联网搜索（通过 Exa API） | allow |

#### `grep` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pattern` | string | 是 | 正则表达式 |
| `path` | string | 否 | 搜索目录（默认工作区根目录） |
| `glob` | string | 否 | 文件过滤模式（如 `*.py`） |
| `case_sensitive` | boolean | 否 | 是否区分大小写（默认 false） |

#### `websearch` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | 是 | 搜索查询（自然语言描述） |
| `num_results` | integer | 否 | 返回结果数（默认 5） |

### 12.4 Shell 工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `bash` | 执行 Shell 命令 | ask |

#### `bash` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `command` | string | 是 | 要执行的命令 |
| `cwd` | string | 否 | 工作目录（默认工作区，须在工作区内） |
| `timeout` | integer | 否 | 超时时间（**秒**，默认 60） |

> **安全提示**：`bash` 工具默认 `ask` 权限，执行前会要求用户确认。可通过权限配置允许特定命令自动执行。

### 12.5 LSP 工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `lsp` | LSP 语言服务器客户端（支持多种操作） | allow |

`lsp` 工具通过 `operation` 参数区分不同操作：

| operation | 说明 |
|-----------|------|
| `start_server` | 启动 LSP 服务器进程 |
| `stop_server` | 停止已运行的 LSP 服务器 |
| `symbols` | 获取文档符号列表 |
| `definition` | 跳转到符号定义位置 |
| `references` | 查找符号所有引用 |
| `diagnostics` | 获取文件的诊断信息（错误/警告） |

#### `lsp` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `operation` | string | 是 | 操作类型：`start_server`、`stop_server`、`symbols`、`definition`、`references`、`diagnostics` |
| `file_path` | string | 否 | 文件路径（symbols/definition/references 需要） |
| `query` | string | 否 | 服务器标识符（start_server/stop_server）或符号过滤器（symbols） |
| `line` | integer | 否 | 1-based 行号（definition/references 需要） |
| `column` | integer | 否 | 1-based 列号（definition/references 需要） |
| `server_command` | array | 否 | LSP 服务器启动命令（如 `['pylsp']`），start_server 时需要 |

> **注意**：LSP 服务器必须先通过 `operation='start_server'` 启动后才能进行查询操作。

### 12.6 Git 工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `git` | 执行 Git 版本控制操作 | ask |

GitTool 提供结构化的 Git 本地操作接口，支持以下 8 种操作：

| 操作 | 说明 |
|------|------|
| `status` | 查看工作区状态（已修改、已暂存、未跟踪文件） |
| `diff` | 查看文件差异（支持指定文件、暂存区对比、HEAD 对比） |
| `log` | 查看提交历史（支持限制条数、指定文件） |
| `commit` | 提交更改（需指定提交信息） |
| `add` | 暂存文件（支持指定文件或全部暂存） |
| `branch` | 列出分支或创建新分支 |
| `stash` | 暂存/恢复/列出 stash |
| `show` | 查看指定提交的详细信息 |

#### `git` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `operation` | string | 是 | 操作类型：`status`、`diff`、`log`、`commit`、`add`、`branch`、`stash`、`show` |
| `path` | string | 否 | 文件路径或引用（add/diff/log/show 等操作需要；`show` 的引用默认 "HEAD"） |
| `message` | string | 否 | 提交信息（commit 操作必填） |
| `limit` | number | 否 | 限制返回条数（log 操作，默认 10） |
| `staged` | boolean | 否 | diff 操作：是否对比暂存区；add 操作：是否暂存全部文件 |
| `branch_name` | string | 否 | 分支名称（branch 操作）；**stash 操作的动作类型也通过此参数传递**（`save`/`list`/`pop`/`apply`/`drop`，默认 `save`） |
| `stash_message` | string | 否 | stash 保存时的说明信息（`stash save` 操作） |

> **注意**：GitTool 的 stash 操作**没有 `stash_action` 参数**，动作类型通过 `branch_name` 指定；**没有 `commit_hash` 参数**，`show` 操作的目标引用通过 `path` 传入。

> **注意**：GitTool 仅支持上述 8 种本地操作。对于不支持的操作（如 `push`、`pull`、`fetch`、`merge`、`rebase`、`checkout`、`remote`、`tag`、`reset` 等），请使用 `bash` 工具执行，例如：`bash(command='git push origin main')`。

| `task_id` | string | 否 | 任务 ID（update/delete 需要） |

### 12.8 选择交互工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `selection` | 向用户(人类)展示选项并收集交互式响应 | allow |

`selection` 工具用于当 Agent 需要人类参与决策时，向用户展示选项并收集反馈。

**使用原则**：
- **仅当需要人类输入时使用** — 不要用此工具获取 Agent 可以自行判断的信息

### 12.9 子 Agent 委托工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `task` | 启动专用子 Agent 处理复杂多步骤任务 | allow |

`task` 工具允许主 Agent 将任务委托给专门的子 Agent，在隔离的子会话中执行。

#### 支持的子 Agent 类型

| subagent_type | 说明 |
|---------------|------|
| `general` | 通用子 Agent，具有完整工具访问权限 |
| `explore` | 探索型子 Agent，用于代码库探索和模式发现 |
| `consultant` | 咨询 Agent，预规划分析 |
| `critic` | 审查 Agent，评估工作计划 |
| `executor` | 执行 Agent，计划执行和任务编排 |

> **注意**：隐藏 Agent（compaction、title、summary）不能通过 `task` 工具启动。

#### 子 Agent 执行提示

当主 Agent 调用 `task` 工具启动子 Agent 时，UI 会显示一个提示气泡：

```
[task] Running subagent: 任务描述 (@general)...
```

此提示让用户知道系统正在等待子 Agent 执行完成，防止用户误认为会话卡滞。

**提示行为**：
- 提示在子 Agent 开始执行前立即显示
- 子 Agent 执行期间，其内部工具调用不会实时更新到 UI（避免信息过载）
- 子 Agent 完成后，显示最终结果（包含 `<task_result>` 标签）

#### `task` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `description` | string | 否* | 任务简短描述（3-5 词） |
| `prompt` | string | 否* | 给子 Agent 的详细任务指令 |
| `subagent_type` | string | 否* | 子 Agent 类型 |
| `task_id` | string | 否 | 恢复已有任务的会话 ID |
| `mode` | string | 否 | 执行模式：`single`（默认）、`parallel`、`sequential` |
| `tasks` | array | 否* | parallel/sequential 模式下的任务列表 |

> **注意**：`description`、`prompt`、`subagent_type` 在 `single` 模式下为必填；在 `parallel`/`sequential` 模式下，`tasks` 为必填，顶层三参数不需要。

#### 返回值

`task` 工具返回结果包含：
- `task_id`：子会话 ID，可用于恢复任务
- `<task_result>` 标签包裹的子 Agent 执行结果

### 12.10 辅助工具

| 工具 | 说明 | 默认权限 |
|------|------|----------|
| `skill` | 加载 Skill 指令文档 | allow |

| 参数 | 类型 | 必填 | 说明 |

`plan` 工具的用途是**退出计划模式并返回实现（build）模式**，在规划完成后、开始实现前调用。

#### `mcp-exa` 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | 是 | 自然语言搜索查询 |
| `num_results` | integer | 否 | 返回结果数量（默认 5） |

### 12.11 工具安全

- **路径安全**：所有文件工具使用 `_secure_resolve()` 校验路径，防止 `../` 穿越工作区
- **权限控制**：每个工具调用均经过权限规则匹配，支持按工具名、路径 glob 模式精细控制
- **工作区隔离**：相对路径始终基于工作区根目录解析

## 13. Skill 系统

Skill 系统是 berserker 的扩展机制，允许按需加载特定领域的专业指令和工作流。与内置工具不同，Skill 不直接执行操作，而是向 Agent 注入详细的步骤指南、最佳实践和领域知识。

### 13.1 Skill 是什么

Skill 是一组 Markdown 文档（`SKILL.md`），包含：
- 触发条件（何时应该使用该 Skill）
- 详细的工作流和步骤
- 工具使用示例
- 领域特定的最佳实践

当 Agent 遇到匹配 Skill 描述的任务时，会调用 `skill` 工具加载对应的指令，然后按照指南执行操作。

### 13.2 Skill 搜索路径

Skill 按以下顺序搜索（优先级从高到低）：

| 优先级 | 路径 | 说明 |
|--------|------|------|
| 1 | `.berserker/skills/<skill_name>/SKILL.md` | 项目本地 Skill |
| 2 | `{config_dir}/skills/<skill_name>/SKILL.md` | 全局配置 Skill |

支持的文件名：`SKILL.md`、`skill.md`、`README.md`

### 13.3 内置 Skill

berserker 内置以下 Skill：

| Skill | 说明 | 触发场景 |
|-------|------|----------|
| `playwright` | 浏览器自动化 | 网页交互、截图、表单填写 |
| `frontend-ui-ux` | UI/UX 设计指导 | 无设计稿时的界面实现 |
| `git-master` | Git 高级操作 | 提交、rebase、blame、bisect |
| `dev-browser` | 持久化浏览器会话 | 网页浏览、数据提取 |
| `review-work` | 代码审查 | 实现完成后自动审查 |
| `ai-slop-remover` | 清除 AI 代码异味 | 重构 AI 生成的代码 |

### 13.4 用户安装 Skill

用户可在以下位置安装自定义 Skill：

- **项目级**：`.berserker/skills/my-skill/SKILL.md`
- **全局级**：`{config_dir}/skills/my-skill/SKILL.md`

Windows 全局配置目录：`C:\Users\<用户名>\.config\berserker\skills\`

### 13.5 在 Agent 中使用 Skill

#### 方式一：Agent 自动加载

Agent 在系统提示中会收到可用 Skill 列表，当任务匹配时自动调用 `skill` 工具加载。

#### 方式二：在 `task()` 委托中使用 Skill

`task` 工具**不支持 `load_skills`、`category`、`run_in_background` 参数**（这些参数在 berserker 中不存在）。若需要让子 Agent 使用某个 Skill，直接在 `prompt` 中指示它调用对应的 Skill 工具即可：

```python
task(
  description="提交当前更改",
  subagent_type="general",
  prompt="调用 git-master skill 提交当前所有未跟踪文件，遵循项目提交规范。"
)
```

#### 方式三：手动调用 Skill 工具

Agent 在对话中可直接调用对应技能的工具（工具 ID 即技能名，**无需参数**），例如 `pdf`、`git-master`、`review-work`：

```
git-master
```

加载后，Skill 的完整指令会注入到 Agent 的上下文中。

### 13.6 Skill 与子 Agent 配合

`task` 工具**没有 `category` 参数**，不存在"category 决定执行模型"的机制；子 Agent 使用哪个模型由其自身配置决定，Skill 通过子 Agent 调用 Skill 工具（或独立的技能工具）加载：

```python
task(
  description="代码审查",
  subagent_type="critic",
  prompt="调用 review-work skill 对本次改动进行审查。"
)
```

## 13a. 命令扩展系统

berserker 支持通过 Markdown 文件自定义斜杠命令，无需编写代码。

### 13a.1 命令发现路径

命令按以下优先级加载：

| 优先级 | 路径 | 说明 |
|--------|------|------|
| 1 | `.berserker/commands/<name>.md` | 项目级命令（最高优先级） |
| 2 | `.berserker/command/<name>.md` | 项目级命令（单数目录，同样有效） |
| 3 | `{config_dir}/commands/<name>.md` | 用户级命令 |

> 项目级目录支持 `commands`（复数）与 `command`（单数）两种写法；用户级目录仅 `{config_dir}/commands`。同名命令项目级覆盖用户级。

### 13a.2 命令文件格式

命令使用 Markdown 文件 + YAML frontmatter 定义：

```markdown
---
description: 向用户问候
---

Hello! I'm a custom greeting command.
```

**Frontmatter 字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `description` | string | 否 | 命令简短说明，显示在 `/help` 中 |
| `template` | string | 否 | 模板内容（省略时使用正文） |
| `argument_hint` | string | 否 | 参数提示 |

> **注意**：命令名称取自**文件名**（如 `greet.md` → `/greet`），frontmatter 中的 `name` 字段**不会被使用**。文件正文（或 `template`）作为命令模板内容。

支持子命令目录：`.berserker/commands/database/who.md` → `/database/who`

### 13a.3 模板命令执行

当用户输入斜杠命令时，命令文件的内容会被注入到 Agent 的对话上下文中，Agent 根据指令执行相应操作。

支持位置参数替换：
- `$1`、`$2`、`$3` — 对应第 1、2、3 个参数
- `$ARGUMENTS` — 所有参数的原始字符串

**示例**（`.berserker/commands/create-file.md`）：
```markdown
---
description: 创建文件并写入内容
---

Create a file at path `$1` with the following content:

```
$2
```

Use the `write` tool to create this file.
```

用户输入 `/create-file test.txt Hello World` → Agent 收到指令创建 `test.txt` 并写入 `Hello World`。

### 13a.4 内置命令 vs 自定义命令

自定义命令的优先级高于内置命令（同名时覆盖）。系统启动时自动扫描并注册所有发现的命令。

### 14.3 内置插件：会话计时器 (Session Timer)

记录会话时长、Agent 执行统计和工具调用次数。

**`/timer` 命令：**

| 命令 | 说明 |
|------|------|
| `/timer` | 显示当前会话计时状态 |
| `/timer reset` | 重置计时器和统计数据 |

**编程接口：**
```python
from berserker.plugin.session_timer import get_timer

timer = get_timer()
if timer:
    print(timer.get_elapsed())         # "00:05:32"
```

### 14.4 开发自定义插件

**基本结构：**
```python
from berserker.plugin_system import Plugin

class MyPlugin(Plugin):
    def __init__(self, name, version):
        super(MyPlugin, self).__init__(name, version)

    def activate(self):
        """应用启动时调用"""
        pass

    def deactivate(self):
        """应用关闭时调用"""
        pass

    # --- Agent 钩子 ---
    def on_agent_before_execute(self, agent_name, messages, session_id):
        """Agent 开始执行前"""
        pass

    def on_agent_after_execute(self, agent_name, response, session_id):
        """Agent 执行完成后（可修改 response）"""
        pass

    def on_tool_call(self, tool_name, args, result):
        """工具调用完成后"""
        pass

    # --- 斜杠命令注册（可选）---
    def get_commands(self):
        return [{
            "name": "/mycommand",
            "description": "执行自定义操作",
            "handler": self._handle_mycommand,
        }]

    def _handle_mycommand(self, args, session_id):
        print("执行操作，参数: {}".format(args))
        return None
```

**钩子说明：**

| 钩子 | 触发时机 | 用途 |
|------|----------|------|
| `activate()` | 应用启动 | 初始化资源、启动后台任务 |
| `deactivate()` | 应用关闭 | 清理资源、保存状态 |
| `on_agent_before_execute()` | Agent 执行前 | 记录开始时间、注入上下文 |
| `on_agent_after_execute()` | Agent 执行后 | 记录耗时、修改响应内容 |
| `on_tool_call()` | 工具调用后 | 统计工具使用、审计日志 |

**斜杠命令注册：**

插件可通过 `get_commands()` 注册自定义命令。Handler 签名：`(args, session_id) -> Optional[str]`

- 返回 `None`：session 不变
- 返回新 session ID：GUI 自动切换 session 并更新窗口标题
- 返回 `"__exit__"`：退出应用

> **GUI 输出捕获**：GUI 模式下，handler 的 `print()` 输出会被自动捕获并显示在聊天窗口中。

### 14.5 注意事项

1. **插件类发现**：加载器自动扫描模块中 `Plugin` 的任意子类（不要求类名必须为 `Plugin`）
2. **必须继承** `berserker.plugin_system.Plugin`
3. **钩子异常隔离**：钩子中的异常不会中断 Agent 执行
4. **PyInstaller 兼容**：使用 `spec_from_file_location` 直接按路径加载，不依赖 `sys.path`
5. **全局单例**：通过 `from berserker.plugin_system import plugin_manager` 访问全局管理器

### 15.2 GUI 中的会话管理

GUI 模式提供可视化的会话管理功能：

- 切换工作区后，侧栏自动刷新显示该工作区下的会话列表

## 17. 上下文管理

berserker 提供多层上下文管理机制，防止对话历史超出模型上下文窗口限制。

### 17.1 自动压缩触发

当对话历史接近模型上下文窗口限制时，系统自动触发压缩。压缩行为由 `compaction` 配置段控制：

```json
{
  "compaction": {
    "auto": true,
    "prune": true,
    "reserved": 20000,
    "prune_protect": 40000,
    "prune_minimum": 20000,
    "compact_threshold": 0.8,
    "keep_last_turns": 2
  }
}
```

**参数说明**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `auto` | bool | `true` | 是否自动触发压缩。设为 `false` 后仅手动 `/compact` 触发 |
| `prune` | bool | `true` | 是否启用工具调用内容修剪。修剪会移除旧的工具输出以释放空间 |
| `reserved` | int | `20000` | 保留的 token 缓冲区（为下一次响应预留空间）。触发阈值取 `int(model_limit * compact_threshold)` 与 `model_limit - reserved` 两者中较小者 |
| `prune_protect` | int | `40000` | 保护最近 N 个 token 的工具调用内容不被修剪 |
| `prune_minimum` | int | `20000` | 修剪激活的最小可修剪 token 总量。低于此值时不触发修剪 |
| `compact_threshold` | float | `0.8` | 上下文窗口占用比例阈值。计算为 `int(model_limit * compact_threshold)` |
| `keep_last_turns` | int | `2` | 压缩时逐字保留的最近轮数（按 user 消息切轮，tool 组不拆）；更老的轮次由 AI 摘要 |

**触发示例**（默认 `compact_threshold: 0.8`、`reserved: 20000`，取两者较小者）：
- OpenAI 模型（128K）：在 102.4K token 时触发（0.8 × 128K < 128K - 20K）
- Claude 模型（200K）：在 160K token 时触发（0.8 × 200K < 200K - 20K）
- Gemini 1.5 Pro（2M）：在 1.6M token 时触发（0.8 × 2M < 2M - 20K）

### 17.2 混合压缩策略（Hybrid）

压缩同时使用两类手段，最终结果保证不超过目标 token 预算：

**手段一：修剪旧工具输出（Pruning）**
- 移除最早的工具调用结果
- 保护最近 `prune_protect`（默认 40K）token 不被修剪
- 可修剪 token 总量需超过 `prune_minimum`（默认 20K）才激活修剪
- 修剪行为受 `prune` 配置开关控制；已修剪消息会记录到 `pruning_state` 表，避免重复修剪

**手段二：AI 驱动的混合摘要（Hybrid Summarization）**
- 将对话按 user 消息切分轮次（assistant 工具调用与 tool 组永不拆分，保证保留尾部始终对 API 安全）
- 最近的 `keep_last_turns`（默认 2）轮**逐字保留**（tail），上限为预算的 30%
- 更老的轮次交给隐藏 `compaction` Agent，生成**五段式结构化摘要**（目标、指令、发现、已完成、相关文件/目录）
- 摘要以 `assistant` 角色写入（而非 system），避免多 system 消息问题
- 若 AI 调用失败或返回为空，使用占位摘要 `"[Previous conversation summarized: {n} messages compressed to save tokens]"`
- 若组装结果仍超预算，则从旧到新丢弃 tail 轮次；摘要本身超限时截断文本

**触发时机**：分为回合前（`token_overflow`）、工具循环内（`loop_token_overflow`）、上下文超限重试（`context_retry`）三类，均经 `_execute_compaction` 统一执行。

### 17.3 Git 快照追踪

压缩过程中，系统会自动创建 Git 快照以追踪文件变更：

- 使用 `git stash create` 在压缩前创建快照（不修改工作区）
- 记录两次压缩之间的文件变更统计（新增行数、删除行数、变更文件数）
- 快照信息随压缩统计一起报告，方便追踪会话期间的工作进展
- 压缩前还会自动清理已完成的任务（todos）

### 17.4 手动压缩

在交互模式中，可随时手动触发压缩：

```
/compact
```

压缩完成后会显示详细统计信息，包括：
- 压缩前后的 token 数量
- 修剪统计（修剪的 token 数、受保护的 token 数）
- Git 快照信息（如有变更）
- 归档信息（见下）

**归档机制**：无论自动还是手动压缩，替换消息前都会将原消息归档到 `message_archive` 表（手动压缩的 reason 标记为 `manual-compact`），因此压缩前的完整历史始终可恢复。可通过 `list_archives(session_id)` / `get_archive(archive_id)` 读取。

适用于：
- 对话历史较长，感觉响应变慢
- 完成一个阶段性任务后
- 准备开始新任务前

### 17.5 配置上下文窗口

上下文窗口在 **provider 的 `models` 列表内**按模型配置（非顶层键）：

```json
{
  "providers": {
    "openai": {
      "type": "openai",
      "api_key": "{env:OPENAI_API_KEY}",
      "models": [
        {"name": "gpt-4o", "context_window": 128000, "max_output_tokens": 16384, "compaction_buffer": 20000}
      ]
    }
  }
}
```

- `context_window`（int）：模型最大输入 token（默认 128000）
- `max_output_tokens`（int）：单次输出上限（默认 4096）
- `compaction_buffer`（int）：压缩预留缓冲（默认 20000）

> **注意**：若某模型未配置元数据，将使用内置默认值（`context_window` 128000、`max_output_tokens` 4096、`compaction_buffer` 20000）。

### 17.6 工具输出截断与安全限制

单个工具的输出采用动态截断机制，根据当前上下文使用情况自动调整截断阈值：

- **动态截断**：基于当前上下文使用量自动调整截断阈值，确保为后续操作保留足够空间
- **计算公式**：`available = context_limit - current_tokens - reserved`
- **最小截断值**：至少 4096 tokens（即使上下文紧张）
- **reserved 配置**：通过 `compaction.reserved` 配置，默认 20000 tokens
- **向后兼容**：无 `context_info` 时回退到固定 4096 截断

#### 工具安全限制

为防止资源耗尽和意外数据丢失，以下工具设有硬性限制：

| 工具 | 限制类型 | 限制值 | 超出行为 |
|---|---|---|---|
| **Write** | 文件大小 | 1 MB | 抛出 `ToolError`，不写入文件 |
| **Read** | 读取大小 | 100 KB | 自动截断，添加 `[Truncated]` 提示 |
| **Ls** | 目录条目数 | 500 个 | 截断显示，添加 `[Truncated]` 提示 |
| **Glob** | 匹配结果数 | 100 个 | 截断显示，添加 `[Truncated]` 提示 |
| **Bash** | 输出大小 | 100 KB | 自动截断 stdout/stderr |

#### 写保护机制

- **已存在文件警告**：使用 Write 工具覆盖已存在文件时，输出会包含警告信息，建议使用 Edit 工具代替
- **Bash 文件读取拦截**：当检测到简单的 `cat`/`head`/`tail`/`type` 命令时，返回警告并建议使用 Read 工具（提供行号和编码自动检测）

> **注意**：旧版 `compaction_buffer` 配置已被 `compaction.reserved` 取代，但旧配置仍向后兼容。

### 17.7 Token 计数性能

berserker 使用精确的 Token 计数机制，支持多种模型的编码方式：

#### Qwen 模型 Token 计数

对于 Qwen 系列模型（qwen、qwq、qwen-turbo、qwen-plus、qwen-max），使用纯 Python BPE tokenizer：

**首次加载性能**：
- Vocab 文件大小：约 2.5 MB
- Mergeable ranks：151,643 个
- 加载时间：约 1.2-1.8 秒（首次调用时）

**后续调用性能**：
- Tokenizer 被缓存后，后续调用非常快
- 短文本（<100 chars）：约 0.5 ms
- 中等文本（1K chars）：约 10 ms
- 长文本（10K chars）：约 50-60 ms

**Vocab 文件位置**：
- Windows：`C:\Users\<用户名>\.cache\berserker\qwen.tiktoken`
- Linux/macOS：`~/.cache/berserker/qwen.tiktoken`

**性能优化建议**：
1. **启动时预加载**：首次调用会有 1.2-1.8 秒延迟，建议在应用启动时预加载 tokenizer
2. **使用缓存**：Tokenizer 实例会被全局缓存，避免重复加载
3. **考虑 tiktoken**：如果系统支持 Rust 扩展，使用官方 tiktoken 库会更快

#### 其他模型 Token 计数

对于 OpenAI、Claude、Gemini 等模型，使用 tiktoken 库（需要 Rust 扩展）：

- 加载速度：快（毫秒级）
- 计数速度：快（毫秒级）
- 依赖：需要安装 `tiktoken` 包

#### 语言感知估算

当 tiktoken 或 Qwen tokenizer 不可用时，使用语言感知估算：

- 基于文本语言（中文、英文、代码等）估算 token 数
- 精度较低，但速度快（毫秒级）
- 作为 fallback 机制

## 18. 性能调优

### 18.1 启动性能优化

**Token 计数预加载**：

对于使用 Qwen 模型的场景，首次 Token 计数会有约 1.2-1.8 秒的延迟。可通过以下方式优化：

1. **配置文件预加载**：在启动时自动加载 Qwen tokenizer
2. **使用其他模型**：OpenAI/Claude 模型的 tiktoken 加载更快

**建议配置**：

```json
{
  "agents": [
    {
      "name": "berserker",
      "model": "gpt-4o"  // 使用 tiktoken，加载更快
    }
  ]
}
```

> **注意**：覆盖内置 Agent（`berserker`）需要走旧版配置路径（`AgentManager.load_from_config`），详见 §11.5.1 的说明。

### 18.2 工具输出截断配置

根据任务类型调整 `max_tool_output_chars`：

| 任务类型 | 建议值 | 说明 |
|---------|--------|------|
| 代码审查 | 8000 | 只需查看关键代码片段 |
| 日志分析 | 50000 | 需要查看完整日志 |
| 文件搜索 | 64000 | 默认值，平衡性能与信息量 |
| 大文件处理 | 100000 | 需要查看完整文件内容 |

**配置示例**：

```json
{
  "agents": [
    {
      "name": "log-analyzer",
      "options": {
        "max_tool_output_chars": 50000
      }
    }
  ]
}
```

### 18.3 工具迭代次数配置

根据任务复杂度调整 `max_tool_iterations`：

| 任务类型 | 建议值 | 说明 |
|---------|--------|------|
| 简单查询 | 10 | 单次工具调用即可完成 |
| 代码修改 | 50 | 需要多次工具调用 |
| 复杂重构 | 100000 | 默认值，支持复杂任务 |

## 19. 常见问题

### 19.1 配置未生效？

检查配置文件的搜索顺序：
1. 确认 `--project` 指向正确的目录
2. 确认项目目录下有 `berserker.json` 或 `berserker.jsonc`
3. 使用 `--verbose` 查看调试输出

### 19.2 API 连接错误？

- 确认环境变量已正确设置（如 `OPENAI_API_KEY`）
- 确认网络可以访问 API 端点
- 检查配置文件中的 `{env:VAR_NAME}` 语法是否正确

### 19.3 文件操作被拒绝？

- 确认文件路径在工作区内
- 检查权限配置是否允许该操作
- 写/编辑操作默认需要用户确认

### 19.4 如何查看可用模型？

```bash
berserker.exe models
```

### 19.5 如何查看已配置的 Provider？

```bash
berserker.exe providers
```

### 19.6 如何查看已配置的 API 密钥？

```bash
berserker.exe auth
```

密钥会显示为掩码格式（如 `sk-...abcd`）。

> **注意**：`auth` 仅**显示已掩码的密钥**，不是交互式凭据配置工具。

### 19.7 Python 版本要求

berserker 兼容 **Python 3.8.10**，使用 type comments 语法，不使用 `match/case` 或 `str | None` 联合类型语法。

### 可配置参数汇总

| 参数 | 位置 | 类型 | 默认值 | 说明 |

| `max_tool_iterations` | agents[].options | int | 100000 | 工具调用循环最大迭代次数 |

| `prune_minimum` | compaction | int | 20000 | 修剪激活的最小可修剪 token |
| `compact_threshold` | compaction | float | 0.8 | 上下文窗口占用比例阈值 |
| `keep_last_turns` | compaction | int | 2 | 压缩时逐字保留的最近轮数 |
| `subagent_timeout` | 根级别 | int | 3600 | 子 Agent 执行超时时间（秒） |
